# ADR-0003：付费推理预算预留协议

- 状态：已接受；领域模型与服务已实现，运行接线与并发验证待完成
- 日期：2026-07-13
- 默认预算：`0`（禁止付费调用）

## 背景

仅在请求完成后写使用日志不能阻止并发超支。多个 worker 可能同时看到“仍有余额”并各自发送付费请求；超时和重试也可能重复扣费。现有 ModelUsageLog 可记录使用，但未确认具备原子预留、提交和释放协议。

## 决策

所有付费候选请求在外发前必须获得预算预留。本地 Provider 不消耗“付费 API 预算”，但可以在独立成本账本记录电力与折旧。

当前实现使用六位小数 Decimal 并携带币种，禁止二进制浮点金额：

```text
available = limit - committed - active_reservations
```

当前预留生命周期：

```text
active -> settled
       \-> released
       \-> expired
       \-> ambiguous -> manual_review
```

## 预留规则

1. 默认项目预算为 `0`，任何付费预留都失败。
2. 路由器按当前价格表计算保守估算，包含最大 token、图片/视频参数和重试上限。
3. 在数据库事务中锁定预算账户并原子检查余额。
4. 当前唯一范围是 `policy + idempotency_key`；调用方应把工作项/attempt 语义编码进稳定 key。
5. 预留成功后才允许发送外部请求。
6. 成功或确认产生费用后提交实际金额；未使用部分释放。
7. 确认未发送或明确失败时释放。
8. 外部是否接受未知时转 `ambiguous`，再进入 `manual_review`；两种状态都冻结预留金额，禁止自动释放或过期。

## 并发与一致性

- 预算账户更新必须使用行锁、条件更新或等价串行化机制。
- 幂等键重复请求返回原预留，不创建第二笔。
- 提交和释放是互斥终态，重复调用返回原结果。
- 实际金额超过预留但仍在硬限额内可按实际结算；超过硬限额且不允许 overage 时拒绝结算并人工对账。
- 价格表版本、估算参数和外部请求 ID 必须可审计。
- worker 崩溃不能让预留永久占用；过期清理需先判断外部请求状态。

## 已实现数据字段

预算策略：币种、周期、软/硬限额、已结算、已预留、是否允许超额、耗尽动作、TTL 和有效期。

预留：策略、项目、可选工作项 ForeignKey（同一工作项可有多次 fallback 预留）、幂等键、状态、估算/预留/结算金额、币种、过期/结算/释放时间和脱敏 details。Provider、价格版本和外部请求 ID 由调用方写入 details 或后续扩展显式字段。

所有金额字段使用 Decimal，当前量化到 `0.000001`。

## 错误语义

| 情况 | 行为 |
| --- | --- |
| 预算为 `0` | 外发前返回 `budget_not_available` |
| 余额不足 | 不创建外部请求；可等待人工加预算 |
| 价格未知 | fail closed |
| Provider 超时且接受状态未知 | `ambiguous`，随后 `manual_review`，冻结预留 |
| 取消前已产生费用 | 提交实际费用，剩余释放 |
| 数据分类禁止外发 | 不进入预算预留，直接拒绝付费路由 |

## 被否决方案

### 请求完成后再记账

无法阻止并发超支，且失败/超时账目不完整。

### 用 Redis 计数作为唯一账本

缓存失效或恢复会丢失财务状态。Redis 可做限流，预算事实应持久化并可事务更新。

### 预算 `0` 表示不限额

被否决。`0` 明确表示禁用付费，避免默认配置造成意外成本。

## 影响

优点：并发下可控成本，失败可对账，审计清晰。

代价：需要价格版本、持久化事务、补偿任务和 Provider 对账能力；某些 Provider 不提供请求查询时必须采用更保守策略。

## 回滚

```powershell
$env:AI_ROUTER_V2_ENABLED='false'
$env:AI_ROUTER_V2_SHADOW_MODE='true'
```

同时设置项目 `allow_paid_fallback=false`、`allow_cloud_data_transfer=false`、`project_budget_cny=0` 和硬预算 `0`。不能绕过预留继续付费请求；既有预留逐笔结算、释放或对账。

## 验证要求

- 100 个并发预留不能超过限额。
- 幂等重放只产生一笔预留和一次扣费。
- worker 在发送前、发送后、提交前崩溃均可恢复。
- 预算 `0`、价格未知和数据禁止外发都在网络请求前失败。
- 取消、超时、部分使用和 Provider 对账有自动化测试。
- Usage Log 与预算提交可按工作项和外部请求 ID 对齐。
