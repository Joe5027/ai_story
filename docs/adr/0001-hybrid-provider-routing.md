# ADR-0001：本地优先的混合 Provider 路由

- 状态：已接受；领域核心已实现，运行接线与验证待完成
- 日期：2026-07-13
- 决策者：AI Story 维护者（待正式确认）
- 关联：[本地 AI 文档](../local-ai/README.md)

## 背景

AI Story 已有 Provider、Model、ProjectModelConfig、优先级、限流、负载均衡策略和使用日志，可为不同工作流阶段选择多个 Provider。当前文本客户端可调用 OpenAI 兼容服务，ComfyUI 客户端可承载文生图和图生视频。

本次新增确定性路由与预算领域服务，但只有在迁移、API/任务接线和并发测试通过后，才能证明运行链路会阻止意外外发。

## 决策

采用“本地优先、付费显式授权、未知即拒绝”的混合路由：

1. 每个任务先根据能力、项目配置、数据分类、模型/工作流验证状态筛选候选。
2. 已验证的本地 Provider 优先。
3. 本地候选容量不足或失败时，只有 `allow_paid_fallback=true`、`project_budget_cny>0`、素材出站已由授权人带时间戳批准、价格可估算且预算预留成功，才考虑 `paid_fallback`。
4. 默认付费预算为 `0`，表示禁止付费调用。
5. 路由选择固定到工作项，重试不得静默切换模型、工作流或数据边界。
6. 所有失败采用有限重试；不确定外部请求是否已发生时先对账，不立即重放。

目标配置：

```powershell
$env:AI_ROUTER_V2_ENABLED='false'       # 上线前默认关闭
$env:AI_ROUTER_V2_SHADOW_MODE='true'   # 默认只读对比
```

## 路由顺序

```text
校验任务
  -> 过滤能力/数据分类/验证状态
  -> 尝试健康且有容量的本地候选
  -> 本地不可满足？
       -> 付费回退未授权：失败
       -> 已授权：预留预算 -> 固定付费候选 -> 提交
```

健康探测失败、许可证未知、模型未安装、基准未通过或预算状态未知都不能视为可路由。

## 数据模型要求

工作项至少记录：候选集合版本、选择原因、Provider/Model/工作流版本、数据分类、是否允许付费、预算预留 ID、外部请求 ID、幂等键和终态。

旧 ProjectModelConfig 仍服务现有阶段绑定；新路由以 ProjectAISettings、GenerationRoute/Target 和 GenerationProfile 为控制事实，不在 Runtime Agent 中建立第二套项目配置。

## 被否决方案

### 只用云 API

实现简单，但持续费用和数据外发风险高，无法利用本地硬件。

### 只用本地模型

成本可控，但在本地质量、容量或兼容性不足时没有受控兜底。项目仍可通过预算 `0` 选择这种运行模式。

### 本地失败后自动无条件付费

被否决。它会把基础设施故障转换为费用和隐私事件。

### 仅靠 Provider 优先级

优先级缺少数据分类、预算事务、工作项幂等和失败不确定性，不能单独承担安全路由。

## 影响

优点：默认控制成本和数据外发；保留经批准的质量/容量回退；决策可审计。

代价：需要实时健康、能力登记、预算预留、统一工作项和更完整的测试；路由失败会更明确而不是“尽量生成”。

## 回滚

设置：

```powershell
$env:AI_ROUTER_V2_ENABLED='false'
$env:AI_ROUTER_V2_SHADOW_MODE='true'
```

同时设置项目 `allow_paid_fallback=false`、`allow_cloud_data_transfer=false`、`project_budget_cny=0` 和硬预算 `0`，审计/撤销云出站授权，再恢复已验证 Provider。运行中请求、预留和工作项仍需对账。

## 验证要求

- 预算为 `0` 时无外部付费请求。
- 数据分类禁止外发时，即使本地故障也不回退。
- 并发路由不超过 Provider 限流或项目预算。
- 超时、不确定结果、取消和 worker 重启不重复执行/扣费。
- 切换开关后旧 worker 与缓存配置不继续混合路由。

## 未决事项

- 各阶段的质量与延迟门槛需真实基准确定。
- ProviderPriceRate 已记录人民币汇率、来源、条件和版本；自动价格同步与汇率刷新策略仍待确定。
- 数据分类的管理 UI 与审批记录待设计。
